Every EDI Onboarding Is a Data Project

By Nion Hoq · Nov 18, 2026 · 3 min read

The connection is the easy part.

AS2 or SFTP. Certificates exchanged, endpoints tested, a file moves from one server to the other. In most onboardings I have run, that work takes an afternoon.

Then the real work shows up, and it has nothing to do with the connection.

The partner's item numbers do not match your item master. Their case quantity is 12, your system expects eaches. Half the ship-to addresses are missing postal codes. The GTIN in the test 856 does not exist in your catalogue. A location code in the file points at a warehouse that closed two years ago, and everyone on the partner's side still uses it.

None of that is an integration problem. The pipe works fine. The data inside it disagrees with itself.

This is where onboardings actually stall. I have watched go-lives slip by weeks while the project channel kept calling it a mapping issue. It was never the map. A map translates what the data already says. When the item file is wrong, the map faithfully translates the wrong thing, and the failure shows up downstream as a rejected ASN or a receiving dock that cannot match the shipment to the order.

The pattern repeats because onboarding plans are written around the technical checklist. Connectivity test. File format test. Mapping sign-off. The data audit, if it happens at all, happens by accident, usually during user acceptance testing, which is the most expensive possible time to find out that two companies count a case differently.

So I run onboarding in a different order now.

Before the first test file, I ask for three things: the partner's item file, their pack size table, and their location list. We put those next to our own master data and reconcile them on a screen, with a person from each side who can actually decide which value wins. It is unglamorous work. It is also the work the go-live date depends on.

Once the data agrees, the rest of the project gets quiet. The mapping is short work because the fields line up. Testing stops producing surprises, because the surprises were in the data and we already met them. The first live ASN goes out and the dock receives against it, which is the only test that matters.

There is a wider lesson in this for the AI tools now arriving in integration work. A model can draft the map, check the file, and flag the values that break the pattern. It cannot decide that your partner's case of 12 is your each, or that the closed warehouse code should retire. Those are agreements between two businesses, written in data. Somebody has to make them, out loud, before the automation is worth anything.

Connectivity gets the kickoff meeting. Data decides the go-live date.
